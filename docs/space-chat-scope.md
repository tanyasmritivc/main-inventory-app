# Space Ask boundary and completion

The mobile Space sheet previously used the inventory-wide legacy chat route. Its final answer budget was 500 tokens, and live logs showed interrupted model answers. This change adds an optional authenticated `X-Findez-Space-ID` boundary to the existing inventory route and a Space-only answer path with an 8,192-token budget for planning and final generation. No interrupted response is treated as complete.

Inventory authorization runs first; the selected Space is freshly checked in that inventory. Repository reads/updates, model tools, cache keys, private history and reviewed action access are narrowed to the Space. Model-provided Space IDs cannot broaden scope. Unsupported organization-wide tools remain available through main Ask. Existing editor permissions and explicit add/delete confirmations are retained.

Private history is bound by a metadata-only message in existing answer_context JSON. Its assistant role satisfies the existing JSON constraint; its empty content is never rendered, used as model history, or emitted as an answer. The actual first user question remains a separate normal message. world_key stays null so existing inventory action transactions retain their checked contract. No new column, migration or entitlement is required. Old inventory-wide conversations remain in the original inventory history; they are not guessed into a Space.

Main world-chat routes, model generation, tool loop, UI and behavior are unchanged. Existing inventory clients without the Space header keep their behavior. Shared tool dispatch adds only a no-op guard when no Space context exists. Production has additional independent changes in ai.py and ai_agent.py; deployment applies the reviewed delta to a staged live source tree and checks all other files remain unchanged, rather than replacing those files from this checkout.

Validation: 1,530 Python tests passed locally. 34 focused checks passed against staged current production code. Real configured-model QA used a disposable account with two Spaces: four complete responses, separate histories, blocked cross-Space editing, and confirmed add/delete review cards all passed. The initial answer and follow-up took 2.25s and 1.60s in this single run; this is not a latency benchmark. The account was removed and no customer records were used. See the delivery receipt after activation. No production schema change or public App Store submission.
