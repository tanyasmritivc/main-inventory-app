## 2. Things `CLAUDE.md` got wrong or left out (now corrected)

1. **Migration files cannot rebuild the database.** 11 tables are read/written in code with no
   `CREATE` in `backend/supabase/migrations/`: `spaces`, `checkouts`, `team_shares`,
   `team_members`, `parts_catalog`, `user_memory`, `query_logs`, `conversation_sessions`,
   `conversation_history`, `user_plan`, `profiles`. This is the single largest risk in the repo
   and the biggest obstacle to the Azure migration.
2. `gpt-4o-mini` is pinned at **four** sites, not one (`openai_service.py:347, 515, 605`,
   `ai_memory.py:58`).
3. `billing.py` uses `APIRouter(prefix="/billing")` — the "flat include list, no prefixes" rule
   has an exception.
4. `routes/checkouts.py` reimplements shared-space membership resolution inline, duplicating
   `_resolve_owner_for_joined_space` in `routes/items.py`.
5. Four conversation stores are referenced in live code; only `conversations`/`messages` is real.
6. `documents.ai_access_granted` — an undocumented AI-consent gate. Privacy-relevant, and this
   product serves minors.
7. `parts_catalog` already exists but is barcode-keyed with no dimensions and no fuzzy matching.
8. `inventory_cache.dart` is 11 lines of in-memory state, not an offline cache.
9. `low_stock_prefs.dart` is device-local `SharedPreferences` — thresholds don't sync across a team.
10. `bin_label_sheet.dart` prints *space* labels (`findez://space/<name>`). No bin concept exists.
11. `.gitignore` has a malformed final line joining two entries.

## 3. Live defects found

**Severity: high**

- **Two Stripe implementations, both mounted.** `billing.py` (`/billing/*`) and `stripe_routes.py`
  (`/stripe/*`), each with its own webhook. Mobile calls the `/stripe/*` family, so `billing.py`
  looks dead — but it is still routable and still has a live webhook URL. Which one fires depends
  on Stripe dashboard config, not on code.
- **No iOS in-app purchase path.** Payment is Stripe Checkout only. Selling a digital subscription
  from inside an iOS app without StoreKit is an App Store rejection. Blocks pilot distribution.
- **Two sources of truth for the free space limit.** `usage_service.get_usage_count("spaces")`
  counts distinct `items.location`; `spaces_repo.get_or_create_space` counts the `spaces` table.
  They disagree on empty spaces and NULL-`space_id` items.
- **No UPDATE policy on `items`** (`001_init` creates SELECT/INSERT/DELETE only). Invisible while
  everything goes through the service role; breaks immediately if any client queries with a user
  token.

**Severity: medium**

- `usage_service.get_user_plan` queries a nonexistent `user_plan` table; its `except` silently
  returns `"free"` every time. Dead code that looks live.
- `items_repo.check_free_tier_limits` hardcodes 30/3, runs its own inline `is_pro` query, and
  fetches every item row to count them.
- `spaces_repo` `.ilike("name", name)` at lines 55, 114, 143 — `%` and `_` in a space name act as
  wildcards and can match the wrong space.
- 17 bare `catch (_) {}` remain in `mobile/lib`. Read paths are fine; each needs classifying.
- `spaces_repo.space_exists` is dead code.
- Mobile spreadsheet import page is unreachable and mis-wired (on-device `excel` parsing → OOM,
  posts to `/ai_command` instead of `/import/spreadsheet`).
- Import parser reads `rows[0]` as header unconditionally. Fixtures already exist in
  `test-data/import-samples/`.

**Needs live DB to confirm**

- `items.created_at` type — `001_init` says `timestamptz`, a prior dump said
  `timestamp without time zone`. If the dump is right, live schema has drifted from migrations.
- RLS mutual recursion: `team_members.owner_see_members` ↔ `team_shares.member_view_shares`.
  Masked by the service role today; must be resolved before the Azure policy rewrite.
- Whether orphaned items (`space_id IS NULL` with a non-empty `location`) currently exist. The
  rename-empties-a-space bug in `docs/session-handoff-2026-07-30.md` §5 was never closed.

## 4. Product plan vs. what's actually built

The plan's "three real additions" land differently than the brief assumes:

| Planned | Actual state |
|---|---|
| Bin-level location (the stated blocker) | **Genuinely absent.** No `bin` column, no references. Full-stack new work: migration + repo + routes + search surfacing + chat grounding + mobile UI. |
| Seeded vendor parts catalog | `parts_catalog` exists but is barcode-keyed with no dimensions, no SKU seeding, no fuzzy name matching. Roughly 20% built, and built around the barcode path the plan explicitly deprioritises. |
| Notes and photos on the item sheet | Largely built. `item_events` (migration `008`) supports `usage/note/failure/success/restock/photo`, with `GET /items/{item_id}/history` and a shared-space variant. Mostly a surfacing job. |
| Checkout return scan | Checkout exists; `POST /checkouts/return` takes a `checkout_id`, not a scanned bin. Additive. |
| Home bin vs. current bin | Blocked on bins. |
| Search shows the bin | Blocked on bins. |
| Low-stock warnings | Threshold logic exists in mobile but is device-local and unsynced. Needs to move server-side to be useful to a team. |
| Offline read path | **Not implemented.** `inventory_cache` is in-memory only. |
| Reduced UI for joined members | Not implemented. `shared_inventory_page.dart` is 2869 lines and shows the full surface. |

## 5. Recommended order (revised)

1. **Dump the live schema to `010_baseline.sql`.** Nothing else — not bins, not Azure — is safe
   until the repo can describe the database it runs against.
2. Resolve the Stripe duplication and decide the iOS payment story. This gates distribution.
3. Close the rename/orphan bug (§5 of the 2026-07-30 handoff) with the SQL already written there.
4. Single migration: `items.bin` + `items.home_bin` + parts catalog extension, together.
5. Bin QR labels (extend `bin_label_sheet.dart`) + return scan.
6. Import header detection + catalog matching against existing fixtures.
7. Offline read path — swap `inventory_cache` to disk-backed. Required for competition wifi.
8. Reduced member UI.

Items 1–3 are prerequisites, not features. They should be done before the FTC decision in §6 of
the brief is even made, because they are cheap and they are true under either branch.
