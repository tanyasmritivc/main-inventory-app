# Regular scan responsiveness

Candidate only; not deployed yet.

Small scans now identify each detected crop individually in the existing four-worker pool. Up to four detected regions use this scheduling path; larger scans retain the existing two-crop batches. This confines individual reads to one worker wave. This is never an item limit. Grounding, crowded-photo close-ups, all accepted objects, source-coordinate crops, unknown-count rules, saving, destinations and client/main-chat behavior are unchanged. Individual crops retain up to 1280-pixel detail instead of fitting into a roughly 620-pixel contact-sheet tile. Failures retain the detected crop as an explicit unknown, as before.

The work is intentionally limited to the shared extractor. Inspection confirmed the deployed web/mobile preview path emits a durable capture and a terminal done event without waiting for a chat response. A disposable-account candidate HTTP check received exactly one done event, nonempty editable items with image URLs/evidence, and keepalives no more than ten seconds apart. It created no inventory and removed the account and its temporary images. The user's indefinitely loading case was not reproduced by that check; physical-device acceptance remains unverified.

Validation: 62 focused tests, including one/four/eight/nine-object scheduling, full crop pixels, four-worker concurrency, stable mapping, retained large-scene batching, partial failures, save/crop/evidence contracts; full Python suite 1,568 passed. The isolated production candidate also passed all 62 focused tests. No database or native changes.

A normal charger-photo inference-only check took 29.55 seconds before and 21.12 seconds with the candidate. Both identified four items; model detection varied (five versus four regions). This is a single-run comparison, not a guaranteed speed/accuracy improvement. The complete candidate HTTP path took 52.6 seconds, returned four identified items and no unknowns. The current live HTTP path took 44.3 seconds for the same photo (four identified and one unknown); this mixed result does not establish a total latency improvement. A controlled crop-stage benchmark with identical accepted regions is pending, followed by exact-source CI. Shorter JSON prompts and streaming transport probes were also investigated without establishing an end-to-end improvement and are excluded. No claim is made that every scan is faster or that an upstream model timeout has been eliminated.
