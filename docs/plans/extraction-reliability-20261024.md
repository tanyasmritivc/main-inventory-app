# Cluttered photo extraction reliability

The Space upload path recompressed an already resized picker image at 1920px/85%, then synchronously recompressed it at 1280px/80% in ApiClient. Small labels and crop pixels degraded. The mobile candidate prepares one EXIF-correct 2048px/92% JPEG in an isolate, removes the redundant Space/Capture pass, and retains 2048px/92% chat photos. Space extraction keeps the photo for an explicit Retry action on transient failures and displays the public server explanation. The progress label uses the existing reverse-direction shine; no fabricated stage milestones.

The API previously discarded an entire identification batch when one object failed strict validation, retried the whole response, and threw away all grounded crops if every identification call failed. It now validates each region/identity separately, rejects duplicate or missing indices without reassignment, preserves valid siblings, and retains unreadable crops as Unknown Review drafts with unknown count/confidence. Entirely failed grounding remains a visible error. No inventory writes occur until the existing confirmation flow. All item/evidence fields, original-pixel crops, count rules, private storage and provider selection remain.

Real workbench probe: baseline 63.6s, eight regions, six described/two unknown; corrected two-crop implementation 61.9s, eight descriptions, all expected fields. These are individual runs, not latency or accuracy benchmarks. A four-crop contact-sheet experiment timed out both calls and was rejected; a smaller token budget was also rejected. The proven two-crop batches, two workers, 4000-token budget and 100s model deadline remain. Crowded scenes can still take roughly a minute or hit model timeouts; no general latency improvement is claimed.

Validation covers malformed sibling results, invalid boxes, duplicate indices, no paid retry for a usable partial response, unknown Review drafts on detail failure, portrait/landscape/EXIF image preparation, same-photo explicit retry, route cleanup and preview/save boundaries. Release receipts follow below. Physical-device acceptance remains pending.
