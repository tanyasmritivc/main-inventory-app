# Azure vs. season — decision and 4-week plan (2026-08-04)

## Inputs

- Migrating all five pieces to Azure: Postgres, Auth, Storage, hosting, OpenAI.
- Driver is **consolidation, not compliance** — an admin account exists because ftctools.com is
  already on Azure. No external deadline attached to the migration itself.
- **Zero real users today.** Season (FLL/FTC/FRC/VEX) starts in ~4 weeks.

## Recommendation: ship the season on Supabase, move the two safe pieces now

The migration deadline is soft. The season deadline is not — teams organise in the first weeks of
the season and are hard to reach after. That asymmetry decides it.

**But the zero-users argument cuts the other way and deserves a straight answer.** Auth is the one
piece that gets more expensive with users, `user_id` is a FK on effectively every row, and today
there is nothing to migrate. The next window this clean is roughly May–August 2027, because FTC
runs Sept–Feb and FRC runs Jan–April with no real gap between them.

That argument is real. It loses anyway, for one reason: a botched auth cutover at kickoff is
unrecoverable *this season*, while staying on Supabase Auth costs nothing a user can see. Auth
migration is 2–3 weeks of work with no test coverage and one physical test device. Spending that
now means arriving at kickoff with no bins, no offline, and a login system nobody has stress-tested.

### The move that makes deferring auth cheap

Do this small thing now instead, while there are no users:

**Stop assuming `user_id == auth.uid()`.** Introduce an internal `users` table keyed by your own
UUID, with the identity provider's subject as a mapped column. Every other table's `user_id` FK
points at *your* table, not `auth.users`. Then the eventual auth migration re-maps one column
instead of re-keying the entire database.

At zero rows this is a one-hour migration. At ten pilot teams it is a weekend. It converts the
expensive future migration into a cheap one and is worth doing regardless of what else happens.

Note this also removes two existing couplings to Supabase Auth: the
`conversations.user_id → auth.users(id) ON DELETE CASCADE` FK in migration `009`, and the
`supabase/functions/delete-user` edge function.

### What to move to Azure now

Two pieces are independent of the data model and can move in the next two weeks without touching
`user_id`:

- **Render → Azure App Service / Container Apps.** Also fixes the free-tier cold start (50s+),
  which currently breaks the mobile app on first open — a real pilot-killer. Re-test the SSE byte
  padding in `routes/ai.py:334` on the new host; it may be unnecessary, but delete it only after
  confirming chat still streams.
- **OpenAI direct → Azure OpenAI.** Config-level, but note `gpt-4o-mini` is pinned at four sites
  (`openai_service.py:347, 515, 605`, `ai_memory.py:58`) and Azure OpenAI addresses deployments,
  not model names.

This puts findez.ai on Azure alongside ftctools.com, which satisfies the consolidation goal
visibly, without betting the season on it.

Postgres, Auth and Storage move together as one coordinated cutover in the off-season
(May–August 2027), made cheap by the `users` table above.

## Kill the payment problem instead of solving it

There is no StoreKit path, so Stripe Checkout inside the iOS app is an App Store rejection.
**Make the pilot free.** Ten hand-set-up teams, free for the season. That defers the entire
Stripe/IAP question past the season, and it aligns with the "free for students" commitment that
was already non-negotiable. It also removes the need to reconcile the two mounted Stripe routers
under time pressure — just unmount `billing.py`.

## Four weeks

**Week 0 — prerequisites (~2 days).** True under every branch, so do them first.

1. Dump live schema → `backend/supabase/migrations/010_baseline.sql`. Eleven tables the code uses
   have no `CREATE` anywhere in the repo; nothing downstream is safe until this exists.
2. Verify the orphan query in `docs/session-handoff-2026-07-30.md` §5 and close the
   rename-empties-a-space bug.
3. Unmount `billing.py`; disable the paywall for the pilot.
4. Fix the malformed final line in `.gitignore`.
5. Internal `users` table + `user_id` re-point.

**Week 1 — bins.** One migration adding `items.bin` and `items.home_bin` alongside the parts
catalog extension; both touch `items` and should not be two migrations. Surface `bin` in search
results, item detail, and chat grounding.

**Week 2 — bins in the physical world.** Extend `bin_label_sheet.dart` (currently prints *space*
labels — `findez://space/<name>`) to bin labels. Return-by-scan on `POST /checkouts/return`.
Home-vs-current divergence → put-away list, "found it here", "last seen in X by Y".

**Week 3 — competition-hardening.** Disk-backed offline read path; `core/inventory_cache.dart` is
11 lines of in-memory state today and will not survive an app restart, let alone pit wifi. Reduced
UI for joined members. Move low-stock thresholds server-side — they are device-local
`SharedPreferences` now, so fifteen people each see their own.

**Week 4 — mentor setup flow and buffer.** Create team → import BOM → print labels → share code,
in 30 minutes with no support. Import header detection against the eight fixtures already in
`test-data/import-samples/`. Leave real slack here; there is no CI and regressions only appear on
device.

## Deliberately not in these four weeks

Discover/Collections, documents polish, the Next.js dashboard, business confirm-before-save,
consumer barcode lookup, free-form fastener extraction, and the seeded vendor SKU catalog.
`parts_catalog` exists but is barcode-keyed with no dimensions — seeding it properly with
goBILDA/REV/AndyMark/VEX data is the real moat and deserves the off-season, not a rushed month.
