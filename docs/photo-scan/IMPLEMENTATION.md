# Photo scan card — build175

The existing `ExtractScanning` card is replaced in place. Its stage uses the shared Plum/Rust art and two-pass grain, blurred luminosity photo backdrop, a contained rounded photo and screen-blended sweep. Inter Tight uses the existing registered font. The card supplies actual result counts, horizontal thumbnails, the existing selection state, Review/Retake, and stopped/error retry states. Reduced Motion disables sweep, pulse and slide; large text and narrow layouts scroll safely.

The source API was inspected before implementation. It emits count-free status messages and one complete capture draft. It supplies item names and optional authenticated crop URLs, but no bounding boxes or measured progress. Therefore there are no invented boxes or detections. Real draft tiles reveal 120ms apart; missing thumbnails use the existing cached riso tiles. The bar is presentation-only activity capped at90%, without an accessibility percentage. TestFlight notes describe thumbnails after scanning rather than claiming unsupported live bounding boxes.

`ChatCaptureCard` remains the owner of selection and its existing PATCH action. Review reveals its original review body without saving. Retake calls the existing camera flow. Stop cancels the same stream and generation; retry reuses the retained photo. The note and send actions are unchanged. A completed extraction stays reviewable if its later model reply fails. The preview scrolls above the existing composer on completion. No scan request, API, parser, saved-item logic, backend, schema, other main Ask UI or web source changed.

Validation: 1,351 Flutter tests passed (one existing skip), 86 focused scan/Ask/review checks, clean analyzer, eight native card cases and the real Ask stop/retry/note/viewport case. Native checks cover portrait/landscape, one/twelve results, selection, errors/stopped, Reduced Motion and320pt large-text layout. Native screenshots are in `verification/`.

Five production scans ran through the mobile API on the iOS simulator using disposable accounts and bundled sample photos: portrait8 observations, landscape8, focused charger4, crowded workbench8, isolated bearing1. All received crop URLs and unsaved review drafts. The crowded photo contains many physical parts; twelve-row layout was additionally tested with a deterministic fixture. This validates delivery and presentation, not model-identification accuracy. Both accounts and34 test images were removed; no inventory items were written. Failed-network behavior and cancellation were injected in UI regression checks; physical camera, airplane-mode and VoiceOver acceptance remain unverified. See `live-verification.json`.

Build175 delivery/CI receipts will be recorded after upload. No public App Store submission.
